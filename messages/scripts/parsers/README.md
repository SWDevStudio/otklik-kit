# Парсеры площадок

Один файл на площадку: `messages/scripts/parsers/<имя>.mjs`. Имя латиницей в нижнем регистре, совпадает с `name` внутри файла. Файлы, которые начинаются с `_`, не загружаются: `_template.mjs` служит заготовкой.

Парсер нужен, чтобы вакансию разбирал скрипт. Модель страницу не читает: в её контекст попадает только готовый `vacancy.md`. Поэтому парсер обязан вытащить полный текст вакансии и все поля, какие есть на странице.

## Что экспортирует модуль

```js
export const name = "superjob";
export const channel = "board";
export const hosts = ["superjob.ru"];
export function match(url) {}
export async function extract(src, kit) {}
export async function search(query, opt, kit) {}
```

- `hosts`: домены площадки для списка `probe.mjs --list`. Выбор парсера по ссылке делает только `match`: он получает каждую ссылку по очереди, первый вернувший не `null` и забирает её.
- `channel`: `board` для площадки, где отклик уходит вместе с резюме на ней (письмо прикладывается к отклику, должность рекрутер видит сам); `site` для сайта компании с формой; `telegram` для каналов. Свои каналы `hh` и `habr_career` есть только у встроенных парсеров.
- `match(url)` получает объект `URL`. Ссылка на вакансию этой площадки: вернуть `{ id, url, slug }`, где `url` каноническая ссылка без меток, `slug` вида `<имя>-<id>` (латиница, цифры, дефис). Ссылка этой площадки, но не на вакансию: `{ error: "что не так со ссылкой" }`. Чужая ссылка: `null`.
- `extract(src, kit)` получает `{ id, url, slug, source }` и возвращает вакансию.
- `search(query, opt, kit)` необязательна. Нужна для подбора вакансий командой `--search`. `opt`: `{ remoteOnly, maxPages }`. Возвращает `{ cards, total }`.

Импортировать `../extract.mjs` нельзя: всё нужное приходит в `kit`. Из `../lib.mjs` можно брать `slugify`. Сторонних npm-пакетов нет.

Код со страницы не выполняется никогда: ни `eval`, ни `new Function`, ни `vm`, ни динамический `import()`. Страница чужая, а скрипт работает с правами пользователя. Файлы, процессы и переменные окружения парсеру тоже не нужны. Загрузчик не подключает модуль, в котором есть такие конструкции, и пишет об этом строкой `warn`. Данные из скриптов страницы доставай через `kit.jsonBlobs` и `kit.nuxtState`.

## Поля вакансии

| поле | что | пример |
|---|---|---|
| `title` | должность | `Senior Frontend-разработчик` |
| `company` | компания, для скрытой пусто | `ООО Ромашка` |
| `text` | полный текст вакансии без меню, подвала, похожих вакансий; абзацы через `\n`, пункты списков с `- ` | |
| `salary` | вилка строкой | `от 150000 до 250000 RUR на руки` |
| `location` | город | `Москва` |
| `experience` | требуемый опыт | `3-6 лет` |
| `employment` | занятость | `полная` |
| `work_format` | формат | `удалённо, гибрид` |
| `key_skills` | массив навыков | `["Vue", "TypeScript"]` |
| `date_posted` | дата публикации | `2026-09-20` |
| `archived` | вакансия закрыта | `true` |
| `letter_required` | письмо обязательно | `true` |
| `test_required` | у отклика есть тест работодателя | `true` |
| `contacts` | контакты из вакансии | `Анна, hr@x.ru` |
| `method` | как получено, `<имя>/<via>` | `superjob json/http` |

Обязательны `title` и `text`. Остальное заполняй, если оно есть на странице или в данных страницы. Поля нет: не пиши ключ.

## Карточка выдачи для search

`{ id, url, title, company, salary, topRub, remote, exp, experience, responses, closed, letter, test }`

- `url` такая, что `match(url)` её узнаёт.
- `topRub`: верх вилки в рублях числом или `null`.
- `remote`: `true`, `false` или `null`, если формат неизвестен.
- `exp`: `none`, `1-3`, `3-6`, `6+` или пустая строка.

## Что лежит в kit

- `kit.page(url, { allowBrowser, maxAgeDays, headers })` → `{ html, via }`. Кэш на 7 дней, пауза между запросами к одному хосту, распознавание капчи, запасной путь через headless Chrome. Другие способы ходить в сеть не используй.
- `kit.json(url, opt)` → `{ data, via }` для JSON API площадки.
- `kit.ldJobPosting(html)` → объект schema.org JobPosting или `null`; `kit.fromJobPosting(jp)` → поля вакансии из него.
- `kit.jsonBlobs(html)` → `[{ index, kind, size, data }]`: JSON из `<script type=...json>`, `window.__STATE__ = {...}`, `JSON.parse("...")`, `<template>`.
- `kit.nuxtState(html)` → данные сайта на Nuxt: `window.__NUXT__ = (function(a,b){...}(...))` из Nuxt 2 разбирается как литерал без выполнения кода, `__NUXT_DATA__` из Nuxt 3 разворачивается из формата devalue. Не Nuxt: `undefined`.
- `kit.balanced(text, start)` → подстрока от `{` или `[` до парной скобки.
- `kit.htmlText(html)`, `kit.ent(s)`, `kit.meta(html, "og:title")`, `kit.mainText(html)`, `kit.renderDom(url)`.
- `kit.follow(url, name)` → вакансия, разобранная парсером площадки-оригинала, или `null`, если своего парсера у ссылки нет. `name` это имя твоего парсера, чтобы не зациклиться.
- `kit.NetError`: бросай его, когда площадка не отдала данные (пост удалён, нужна авторизация). Любая другая ошибка считается поломкой парсера.

## Агрегаторы

Агрегатор перепечатывает вакансии с других площадок. Если на странице вакансии есть ссылка на оригинал (hh.ru, career.habr.com, getmatch.ru и т.п.), сначала попробуй `kit.follow(ссылка, name)` в try/catch: вернулась вакансия, отдай её как есть. Тогда письмо ляжет в каталог оригинала, дубль с той же вакансией на hh не появится, и все поля возьмёт парсер оригинала. `null` или ошибка: разбирай страницу агрегатора сам. Ссылку на оригинал ищи в данных страницы и в кнопке «Откликнуться»; редирект вида `/go?url=...` раскодируй.

## Проверка

```
bun messages/scripts/probe.mjs <ссылка>                        структура страницы: JobPosting, json-блоки, пути к полям, api-адреса
bun messages/scripts/probe.mjs <ссылка> --blob 3 --path a.b.0   кусок json-блока
bun messages/scripts/probe.mjs <ссылка> --grep "salary"         места в html с контекстом
bun messages/scripts/probe.mjs <ссылка> --parser <имя>          что вернёт парсер и оценка качества
bun messages/scripts/probe.mjs --search <имя> --query "vue"     первая страница выдачи
```

Парсер готов, когда `--parser` на двух разных вакансиях площадки даёт `quality: full`, текст без мусора страницы и все поля, которые видны на странице.
