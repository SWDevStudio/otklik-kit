---

Задание одной строкой: `host=<хост> url=<ссылка на вакансию> [url=<вторая ссылка>] [fix=<имя парсера>] [search=<ссылка на страницу поиска>]`. Вопросов не задавай.

Цель: модуль `messages/scripts/parsers/<имя>.mjs`, который по ссылке этой площадки возвращает вакансию целиком со всеми полями. Страницы в контекст не тащи: смотри на них только через `probe.mjs`, короткими выборками.

## Ход работы

1. Прочитай `messages/scripts/parsers/README.md` (договор парсера) и `messages/scripts/parsers/hh.mjs` как образец. С `fix=` прочитай ещё сломанный парсер. Другие файлы проекта не открывай.
2. Имя парсера: короткое имя площадки латиницей (`superjob`, `geekjob`, `getmatch`). Для сайта одной компании: имя компании. С `fix=` имя уже задано.
3. Разведка: `bun messages/scripts/probe.mjs <url>`. Вывод показывает JobPosting, json-блоки с путями к полям (title, description, salary, company, skills и т.п.), api-адреса и результат общего разбора. Дальше:
   - поле лежит в json-блоке: `probe.mjs <url> --blob N --path a.b.c`, чтобы увидеть его форму;
   - данных в блоках нет: `probe.mjs <url> --grep "<regex>"` по кускам html (класс блока с описанием, слово «Зарплата», «Опыт работы»);
   - страница собирается скриптами и в html пусто: попробуй api-адрес из вывода через `kit.json` или повтори разведку с `--browser` и в парсере используй `kit.page(url)` (браузер он включит сам, если http не отдал страницу).
   Весь html через Read или cat не открывай никогда. Запросы в сеть только через probe.mjs и kit.
4. Приоритет источников в парсере: JSON данных страницы или API, затем JobPosting, затем html по устойчивым признакам (id, data-атрибуты, семантические классы; хэш-классы вида `css-1x2y3z` не годятся). Текст вакансии: только описание, без меню, подвала, блока «похожие вакансии», кнопок и cookie. Площадка перепечатывает чужие вакансии: сделай переход к оригиналу по разделу «Агрегаторы» из README.
5. Напиши модуль по договору из README: `name`, `hosts`, `channel`, `match`, `extract`. Код без комментариев, в стиле hh.mjs, без npm-пакетов, без импорта extract.mjs. Код со страницы не выполняй: `eval`, `new Function`, `vm` и `import()` запрещены, загрузчик такой модуль не подключит; данные Nuxt бери через `kit.nuxtState`, остальное через `kit.jsonBlobs`. Площадка не отдаёт вакансию без входа или отвечает капчей и через браузер: бросай `kit.NetError` с понятной причиной.
6. Проверка: `bun messages/scripts/probe.mjs <url> --parser <имя>` на каждой ссылке из задания. Нужны `quality: full`, текст без предупреждений о мусоре и все поля, которые ты видел на странице при разведке. Не прошло: поправь и проверь снова, всего не больше 4 кругов.
7. С `search=`: разведай страницу поиска тем же способом, напиши `search(query, opt, kit)` по договору и проверь `bun messages/scripts/probe.mjs --search <имя> --query "<запрос>"`: карточки должны иметь id, url, title, а ссылки из выдачи узнаваться `match()`. Если в задании нет ссылки на вакансию, возьми две из выдачи и проверь на них `--parser`.
8. Верни одну строку: `parser <имя> | <путь к файлу> | quality <full|partial> | поля <список заполненных> | search <yes|no>` или `fail <имя или хост> | <причина одной фразой>`.
