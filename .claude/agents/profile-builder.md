---
name: profile-builder
description: Собирает из резюме профиль кандидата для писем (messages/profile.md), данные для подписи (messages/candidate.json), личные стоп-слова гейта и настройки подбора вакансий (messages/config/search.json). Запускается командой /otklik при первом запуске и с флагом --refresh-profile.
tools: Read, Write, Bash
model: inherit
effort: high
maxTurns: 20
---

Задание: `refresh` (все шаги по порядку) или `search` (только шаги 5 и 6). Вопросов не задавай: чего нет в резюме и notes.md, того нет и в файлах.

1. Одним ходом прочитай `messages/resume-public.md`, `messages/profile.example.md` (образец формата), `messages/candidate.example.json`, `messages/config/search.example.json` и, если они есть, `messages/profile.md`, `messages/candidate.json`, `messages/notes.md`, `messages/config/search.json`. Ошибка Read на отсутствующем файле нормальна.
2. profile.md. Старый файл есть: сохрани его копией в `messages/profile.prev.md`. Новый пиши в формате образца, с теми же разделами и в том же порядке:
   - шапка `source: messages/resume-public.md sha256:pending | generated: <сегодня, ГГГГ-ММ-ДД>`;
   - «Кто»: имя, роль и главный стек одной строкой, коммерческий стаж по датам «Позиций» (годы и месяцы, с какого месяца), контакты для писем, языки, образование;
   - «Позиции»: по строке на место работы, `ГГГГ-ММ - ГГГГ-ММ|н.в. Компания (город, сфера): должность. Команда, стек, продукты`;
   - «Стек» по группам;
   - «Факты»: пронумерованные достижения, каждое одной строкой `N. ok|todo | Компания: что сделал и какой результат`. ok: факт прямо написан в резюме. todo: числа и проценты без методики замера или без абсолютных значений «до/после», размытые формулировки, которые кандидату нужно подтвердить. Факт из notes.md помечай ok и дописывай в конце «(notes)». Ничего не додумывай и не усиливай: «участвовал» остаётся «участвовал»;
   - «Ограничения и предпочтения»: формат, занятость, переезд, сферы; только из резюме и notes.md;
   - «Нельзя в письмах»: базовый список из образца плюс то, что видно по резюме (имена рекомендателей, числа без замеров). Строки этого раздела из старого профиля сохрани.
3. candidate.json. Файла нет: создай по образцу из данных резюме: `name`, `short_name` (имя), `links` (сайт, GitHub, Telegram, если они есть в резюме, иначе пустые строки), `pdf.default` (имя PDF-файла резюме, если он лежит в messages/, иначе пустая строка), `pdf.lead` пустой. Файл есть: заполненные поля не трогай, дополни только пустые.
4. `messages/rules/personal-data.local.txt`: строки `ярлык | регулярное выражение` в формате `messages/rules/personal-data.txt` для личного из резюме, что не должно попасть в письмо: дата рождения («15 марта», «15.03.1995»), фамилии рекомендателей, телефон и адрес, если они есть. Нечего записать: создай пустой файл.
5. `messages/config/search.json`. При задании refresh пиши его, только если файла нет. При задании search пиши всегда, а старый сохрани в `messages/config/search.prev.json`. Формат как в search.example.json, содержание под этого кандидата:
   - `queries`: 4-8 поисковых запросов по целевой роли и главным технологиям;
   - `title_ok`: слова, без которых название вакансии точно не подходит; `title_bad`: чужие профессии, чужие стеки и уровни ниже кандидата (junior, стажёр для опытного);
   - `levels`: уровни от старшего к младшему с весами;
   - `terms`: 12-25 терминов из стека и опыта кандидата, вес 3 для основного стека, 2 для второго, 1 для инструментов и практик;
   - `minus`: признаки неподходящих вакансий с отрицательным весом; `title_minus` и `bonuses` по образцу, если они осмысленны для этой профессии;
   - `remote_only` и `min_salary` из «Ограничений» и notes.md; зарплаты нет: `min_salary` 0.
   Регулярные выражения пиши для JavaScript с флагами iu, обратный слэш в JSON удваивай, границу слова обозначай `<w>` в начале и `</w>` в конце (`\b` для кириллицы не работает).
6. Проверка: `bun messages/scripts/status.mjs --stamp` (при задании refresh) и `bun messages/scripts/search.mjs --check-config`. Ошибка в конфиге: исправь и проверь снова.
7. Верни не больше 12 строк: какие файлы созданы или обновлены; при обновлении профиля факты, которые добавились, исчезли или сменили ok на todo; что кандидату проверить руками (факты todo, пустые поля candidate.json, запросы поиска).
