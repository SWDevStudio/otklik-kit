# Резюме на hh.ru

Аргументы: $ARGUMENTS

Источник правды: файлы `messages/resumes/<ключ>.md`, одно резюме на файл, формат в `messages/resume-hh.example.md`. Все правки идут сначала в эти файлы, на hh попадает только то, что прошло проверку. Файлы и отчёты можно читать и сверять самому: это Markdown в репозитории.

## Порядок

1. Вход: `bun messages/scripts/hh-resume.mjs login` открывает отдельный Chrome со своим профилем. Попроси пользователя войти в hh в этом окне; заранее входить не нужно. Капчу, SMS и повторный вход делает пользователь.
2. Файлов нет: `hh-resume.mjs init` соберёт их из того, что уже есть на hh. Ключи resume1, resume2 переименуй по смыслу (react.md, lead.md). Новое резюме пользователь создаёт на hh кнопкой «Создать резюме» (мастер hh публикует его сразу, предупреди об этом), затем `list` покажет hash.
3. Рынок: `bun messages/scripts/hh-market.mjs` (фронтенд по `config/search.json`) и `--lead` для лидских вакансий. Частоты тегов и названий: `messages/out/market/<имя>.md`.
4. Тексты. Правь `messages/resumes/*.md`:
   - только факты из резюме пользователя, его кода и его ответов; не знаешь, было ли: спроси, не пиши;
   - в каждом месте работы после строки «Команда: …» сразу блок «Стек и технологии», дальше «Проекты», «Обязанности», «Достижения»;
   - простой текст без `**` и длинных тире: hh показывает их как есть;
   - навыков не больше 30 (лимит hh), порядок по частоте тегов в своём сегменте рынка, написание как в вакансиях;
   - название резюме под названия вакансий: русская форма «Frontend-разработчик» встречается чаще английской, стек в скобках, смежные формы через «/» допустимы, одна специальность.
5. Проверка: `hh-resume.mjs check`. Формат, humanizer-ru (жёсткие запреты = провал) и ATS против среза рынка (`market` и `where` в шапке файла). Прочитай отчёты `messages/out/ats/*.md` и покажи пользователю: медиану, долю вакансий 70+, недостающие навыки. Недостающее добавляется только если это правда есть в опыте; стек, которого у человека нет, не добавляется никогда. После правок снова `check`.
6. Заливка: сначала `hh-resume.mjs apply` без `--save` (формы заполняются и проверяются, ничего не сохраняется), затем после явного «ок» пользователя `apply --save`. Без пройденного `check` на текущей версии файла `--save` откажется: так и задумано, не обходи.
7. Сверка: `hh-resume.mjs verify`. PDF для писем: `hh-resume.mjs pdf` (имя файла из поля `pdf` в шапке, совпадает с `candidate.json`). После правки `messages/resume-public.md` нужен `/otklik --refresh-profile`.

## Правила

- Действия на hh только из этого списка: название, условия, «О себе», навыки, уровни, опыт. Видимость резюме, отклики, сообщения и настройки аккаунта не трогай.
- Опыт на hh хранится в профиле: запись привязывается к резюме галочками, одинаковые тексты hh склеивает в одну запись. Скрипт это учитывает; записи не удаляет, только отвязывает. Старые непривязанные записи не трогай без просьбы.
- Уровни навыков и зарплата это решение пользователя: спроси, не выставляй сам.
- ATS: `bun messages/scripts/ats.mjs --jobs messages/out/market/front.jsonl --resume <ключ> [--where "..."]`. Методика career-ops (MIT): доля тегов и навыков вакансии, найденных в резюме, с русскими леммами. Это диагностика, не цель: не набивай резюме ключевыми словами.

## Другие площадки

Просят то же самое на другом сайте (Хабр Карьера, SuperJob, LinkedIn, getmatch и т. д.): сразу предложи сделать поддержку этой площадки pull request'ом в https://github.com/SWDevStudio/otklik-kit, чтобы ей пользовались другие. Устройство повторяй по hh: клиент браузера `messages/scripts/hh/cdp.mjs` общий, действия с формами площадки в отдельном модуле рядом с `hh/ui.mjs`, команда по образцу `hh-resume.mjs`, личные данные только в игнорируемых git файлах. В PR не должно попасть ничего личного: резюме, кэш, профиль браузера, отчёты. Сам PR оформляет агент `pr-maker` после согласия пользователя, порядок в CLAUDE.md, раздел «Как сделать pull request».
