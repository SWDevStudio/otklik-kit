# otklik-kit

Набор для Claude Code: команда `/otklik` пишет сопроводительные письма к вакансиям и подбирает вакансии под ваше резюме.

Даёте ссылку на вакансию (hh.ru, Хабр Карьера, Telegram, geekjob, getmatch, агрегаторы, сайт компании) или просите найти подходящие. Скрипт скачивает и разбирает страницу, агент пишет письмо, два проверяющих агента читают его: один сверяет каждое утверждение с резюме, другой смотрит глазами рекрутера. Письмо это 3-4 предложения: чем вы будете полезны компании и как быстро закроете то, чего не хватает по требованиям. Названий в письме нет: компания это «вы» и «в вашем проекте», прошлый опыт описан делом, без мест работы и проектов. Скрипт-гейт ловит штампы, длинные тире, «не X, а Y», личные данные, числа и технологии, которых нет в резюме, перечисление стека, названия компаний и проектов и письма длиннее 4 предложений.

Страницы сайтов модель не читает: их разбирают скрипты, в контекст попадает только готовый текст вакансии. Для площадки, которую набор ещё не знает, агент сначала пишет парсер, проверяет его и только потом берётся за письмо.

Ещё набор ведёт резюме на hh.ru (скилл `hh-resume`): по срезу вакансий подбирает ключевые навыки и название, проверяет резюме ATS-сверкой и humanizer-ru и только потом заливает его на hh через браузер. Подробнее в разделе [«Резюме на hh.ru»](#резюме-на-hhru).

## Что нужно

- [Claude Code](https://claude.com/claude-code).
- [Bun](https://bun.sh) 1.1 или новее: на нём работают все скрипты, npm-пакеты не нужны.
- Chrome или Edge: запасной путь, когда сайт не отдаёт страницу обычному запросу. Другой путь к браузеру можно задать переменной `CHROME_PATH`.
- По желанию: Python 3 с пакетами `razdel` и `pymorphy3` и скилл humanizer-ru. С ними гейт ещё и измеряет «чистоту» русского текста. Без них всё работает, проверка просто пропускается.

```
pip install razdel pymorphy3
npx skills add ilyautov/humanizer-ru
```

На Windows команда `python3` часто оказывается заглушкой Microsoft Store: скрипты сами пробуют `python`, `py` и `python3`.

Не хотите ставить всё это: хватит одного Docker, см. следующий раздел.

## Запуск в Docker

В образе есть Claude Code, Bun, Chromium, `pdftotext`, Python с `razdel` и `pymorphy3` и скилл humanizer-ru. Нужен только Docker (на Windows и macOS Docker Desktop). Из корня проекта:

```
docker compose run --rm otklik
```

Первый запуск собирает образ, это несколько минут. Дальше открывается Claude Code в контейнере, и всё работает так же, как без Docker: `/otklik --refresh-profile`, `/otklik <ссылка>` и так далее.

- Папка проекта смонтирована в контейнер как `/work`. Резюме, профиль, письма и парсеры, которые напишет `parser-writer`, сохраняются прямо в неё, на ваш диск. Файлы вне папки проекта контейнер не видит.
- Вход в Claude: при первом запуске выполните `/login`, откройте ссылку в браузере и вставьте код. Вход хранится в томе Docker `otklik-kit_claude`, повторять его не нужно. Вместо входа можно задать в окружении `ANTHROPIC_API_KEY` или `CLAUDE_CODE_OAUTH_TOKEN` (его выдаёт `claude setup-token`).
- Скрипты запускаются и без Claude:
  ```
  docker compose run --rm otklik bun messages/scripts/import-resume.mjs resume.pdf
  docker compose run --rm otklik bun messages/scripts/status.mjs
  ```
- Образ без humanizer-ru и Python (меньше размер, гейт не измеряет «чистоту»): `docker compose build --build-arg HUMANIZER=0`.
- Обновить Claude Code и остальное: `docker compose build --pull --no-cache`. Сам Claude Code в контейнере не обновляется.
- Часовой пояс по умолчанию `Europe/Moscow`, другой задаётся переменной `TZ`.

## Первый запуск

1. Скопируйте папку целиком и откройте её в Claude Code: корень папки это корень проекта.
2. Положите текст резюме в `messages/resume-public.md`: Markdown или просто текст. Из файла можно так:
   ```
   bun messages/scripts/import-resume.mjs ~/Downloads/resume.docx
   ```
   Для PDF нужен `pdftotext` (пакет poppler).
3. По желанию скопируйте `messages/notes.example.md` в `messages/notes.md` и заполните: зарплатные ожидания, мотивация, факты, которых нет в резюме. Агенты берут их только оттуда и ничего не придумывают.
4. Выполните в Claude Code:
   ```
   /otklik --refresh-profile
   ```
   Агент соберёт из резюме:
   - `messages/profile.md`: факты для писем. Каждый помечен `ok` (можно в письмо) или `todo` (цифры без методики замера и всё, что стоит подтвердить). Факты `todo` в письма не попадают, пока вы не поменяете пометку;
   - `messages/candidate.json`: имя для подписи, ссылки, PDF для писем на почту и в Telegram;
   - `messages/config/search.json`: запросы и веса для подбора вакансий;
   - `messages/rules/personal-data.local.txt`: личное из резюме, что гейт не пропустит в письмо.
5. Проверьте `profile.md` и `candidate.json` глазами. PDF резюме положите в `messages/` под именем из `candidate.json`.

После правки резюме снова выполните `--refresh-profile`: команда сама скажет, что профиль устарел.

## Как пользоваться

```
/otklik https://hh.ru/vacancy/123456
/otklik https://hh.ru/vacancy/1 https://career.habr.com/vacancies/2 https://t.me/channel/345
/otklik --search
/otklik --search --source hh,getmatch --query "vue" --min-salary 250000
/otklik напиши отклик на https://geekjob.ru/vacancy/..., упомяни, что готов к переезду
```

Готовые письма лежат в `messages/jobs/`, по файлу на вакансию: письмо, что проверить перед отправкой, решения агента, вопросы, ответы на которые усилят письмо. Файл с готовым письмом получает префикс `_`. Всё рабочее (разбор вакансии, матрица требований, отчёт проверяющих) лежит в `messages/out/<вакансия>/`.

Правьте письма прямо в `messages/jobs/`: следующие запуски трогают только файлы своих вакансий.

Каждая вакансия сразу проходит ATS-сверку с вашими резюме (`messages/resumes/*.md`, а если их нет, `resume-public.md`): в выдаче подбора и в итоге видно оценку, резюме, которое подходит лучше всего, и навыки вакансии, которых в нём нет. На hh откликайтесь этим резюме; для почты и Telegram к письму прикладывается его PDF (поле `pdf` в шапке файла резюме). Вакансии с оценкой ниже `min_ats` из `config/search.json` подбор не предлагает. Автор письма не приписывает вам недостающие навыки.

Флаги:

| флаг | что делает |
|---|---|
| `--search` | подобрать вакансии по `config/search.json` и написать письма к подходящим |
| `--source hh,getmatch` | на каких площадках искать |
| `--min-ats 60` | отсеять вакансии с ATS-оценкой ниже порога (по умолчанию `min_ats` из `config/search.json`) |
| `--force` | переписать готовое письмо, написать даже к неподходящей или архивной вакансии |
| `--research` | найти факты о компании для связки в письме (дольше, нужен интернет) |
| `--dry` | только скачать и разобрать вакансии |
| `--strict` | проверяющие на Opus |
| `--cheap` | писатель на Sonnet |
| `--parallel` | до трёх агентов одновременно (быстрее, но легче упереться в лимиты) |
| `--browser` | грузить все страницы через headless-браузер |
| `--notes "..."` | заметки ко всем письмам пачки |
| `--refresh-profile` | пересобрать профиль по резюме |

По умолчанию агенты работают по одному: письмо к одной вакансии это 4-6 вызовов модели, и на пачке в 30 вакансий легко упереться в лимит подписки. Всё готовое к этому моменту сохраняется, следующий запуск продолжит с первой вакансии без письма.

Канал отклика определяется по ссылке: на площадках это текст без приветствия, подписи и названия должности (рекрутер видит резюме, имя и вакансию в отклике), для Telegram и почты это письмо с приветствием и подписью, позиция называется в первой фразе, для почты добавляется тема. Если вакансия просит писать на почту, канал переключится сам; вручную: допишите к ссылке `#email` или `#form`.

## Резюме на hh.ru

Скилл `hh-resume` подбирает резюме под рынок и заливает его на hh через браузер: название, условия, «О себе», ключевые навыки, их уровни и опыт. Попросите в Claude Code, например, «обнови резюме на hh под React-вакансии». Можно работать и напрямую командами:

```
bun messages/scripts/hh-resume.mjs login     отдельный Chrome: войдите в hh в этом окне один раз
bun messages/scripts/hh-resume.mjs init      собрать messages/resumes/*.md из того, что уже есть на hh
bun messages/scripts/hh-market.mjs           срез рынка: вакансии, частоты тегов и названий (--lead для лидов)
bun messages/scripts/hh-resume.mjs check     формат, humanizer-ru и ATS против среза рынка
bun messages/scripts/hh-resume.mjs apply     заполнить формы без сохранения; с --save записать на hh
bun messages/scripts/hh-resume.mjs verify    сверить опубликованные резюме с файлами
bun messages/scripts/hh-resume.mjs pdf       скачать PDF резюме с hh для писем
```

- Источник правды это `messages/resumes/<ключ>.md`, по файлу на резюме. Формат с пояснениями: `messages/resume-hh.example.md`. Файлы личные и в git не попадают.
- Заливка с `--save` возможна только после пройденного `check` на текущей версии файла: правка файла сбрасывает отметку.
- ATS (`messages/scripts/ats.mjs`) считает, какая доля тегов hh и навыков из текста вакансии найдена в резюме, с русскими леммами (нужен Python с `pymorphy3`, иначе без них). Методика покрытия взята из `keyword-match.mjs` проекта [career-ops](https://github.com/career-ops-hq/career-ops) (MIT). Синонимы навыков правятся в `messages/config/ats-synonyms.json`. Отчёты: `messages/out/ats/`.
- Зарплата (`messages/scripts/salary.mjs`) берёт рублёвые вилки вакансий из среза рынка, где резюме проходит ATS 50+ и уровень не ниже вашего, приводит их к «на руки» и печатает квартили и ориентир для поля «Зарплата». Это подсказка, резюме скрипт не меняет. Отчёты: `messages/out/salary/`.
- Опыт на hh хранится в профиле, и запись привязывается к резюме галочками. `apply` сам находит нужные записи, создаёт недостающие и отвязывает лишние, но ничего не удаляет. Одинаковые тексты hh склеивает в одну запись.
- Нужен Chrome или Edge с окном: вход в hh делаете вы сами. В Docker без графического окна этот раздел не работает.

## Площадки и парсеры

Каждая площадка это модуль в `messages/scripts/parsers/`. Какие уже есть:

```
bun messages/scripts/probe.mjs --list
```

| модуль | площадка | поиск | что стоит знать |
|---|---|---|---|
| `hh` | hh.ru, hh.kz | есть | зарплата, опыт, формат, навыки, тест работодателя, обязательное письмо |
| `habr` | career.habr.com | нет | |
| `telegram` | t.me | нет | только публичные каналы, ссылка на пост |
| `geekjob` | geekjob.ru | есть | поиск грузится через браузер |
| `getmatch` | getmatch.ru | есть | поиска по тексту у площадки нет: модуль берёт текущую ленту (около 20 вакансий) и фильтрует её сам |
| `hirify` | hirify.me | есть | через API площадки; контакты и ссылка на оригинал скрыты за входом |
| `talentmove` | talent-move.ru | есть | ссылка на оригинал скрыта за входом, вакансия разбирается со страницы агрегатора |
| `wantapply` | wantapply.com | есть | страницы только через браузер; поиск отдаёт первую страницу выдачи |
| `careerspace` | careerspace.app | нет | репосты с hh уходят к парсеру hh |
| `gdtalents` | gdtalents.com, offerclaw.app | нет | поиск на сайте только после входа; отклик на сайте компании |

SuperJob и Работа.ру при сборке набора не отвечали: с IP, с которого собирался набор, оба отдают капчу или «Forbidden» на весь домен. Модули для них напишет `parser-writer` при первой ссылке, если с вашего IP площадка открывается.

Парсер выбирается сам: каждый модуль проверяет ссылку своей функцией `match`, первый узнавший её и разбирает. Нет подходящего модуля: работает общий разбор (разметка schema.org JobPosting или основной текст страницы), и если это площадка с вакансиями или текст получился неполным, агент `parser-writer` пишет новый модуль, проверяет его на двух вакансиях и только потом начинается письмо. Модуль остаётся в папке, и в следующий раз эта площадка разбирается без модели. Сломался модуль (площадка сменила вёрстку): агент его чинит.

Агрегаторы, которые перепечатывают вакансии с hh и других площадок, передают вакансию парсеру оригинала: письмо пишется к оригиналу, и одна и та же вакансия из двух мест не даёт двух писем.

Написать или поправить парсер руками: договор и инструменты описаны в `messages/scripts/parsers/README.md`, заготовка лежит в `_template.mjs`. Проверка:

```
bun messages/scripts/probe.mjs <ссылка>                      что есть на странице
bun messages/scripts/probe.mjs <ссылка> --parser <имя>       что вернёт парсер
bun messages/scripts/probe.mjs --search <имя> --query "vue"  выдача поиска
```

## Что где лежит

```
.claude/skills/otklik/SKILL.md   команда: порядок шагов
.claude/agents/                          letter-writer, fact-verifier, employer-review, company-scout, parser-writer, profile-builder, pr-maker
.claude/settings.json                    разрешения, чтобы скрипты и агенты не спрашивали подтверждения на каждый шаг
messages/scripts/                        загрузка, гейт, сводка, подбор, probe
messages/scripts/parsers/                парсеры площадок
messages/rules/                          штампы, личные данные, разрешённая латиница для гейта
messages/config/search.json              подбор вакансий: запросы, фильтры, веса
.claude/skills/hh-resume/SKILL.md        резюме на hh: рынок, ATS, заливка
messages/scripts/hh-resume.mjs, hh/      заливка резюме на hh: клиент браузера без npm-пакетов и действия с формами
messages/scripts/hh-market.mjs, ats.mjs, salary.mjs  срез рынка hh, ATS-сверка, вилка зарплаты
messages/resumes/                        ваши резюме для hh в Markdown (личное)
messages/*.example.*                     образцы профиля, candidate.json и заметок
docker/, compose.yaml                    образ со всеми программами для запуска в Docker
```

Личное (резюме, профиль, заметки, письма, кэш страниц) перечислено в `messages/.gitignore`. Если держите папку в git, команда предупредит, когда такой файл всё же попал в репозиторий.

## Поддержка новых площадок

Попросили агента сделать то, чего набор ещё не умеет, на другой площадке (резюме на Хабр Карьере или SuperJob, подбор вакансий на новом сайте): агент сделает это и предложит отправить результат pull request'ом в [SWDevStudio/otklik-kit](https://github.com/SWDevStudio/otklik-kit), чтобы площадкой пользовались все. То же с парсерами, которые пишет `parser-writer`. PR оформляет агент `pr-maker`: проверяет, что ничего личного не уходит (всё из `messages/.gitignore`, `candidate.json`, `config/search.json`, личные данные из `rules/personal-data.local.txt`), собирает коммит в отдельной ветке через `git worktree`, не трогая вашу рабочую папку, и открывает PR через `gh`. Без `gh` вы получите ссылку на страницу создания PR и готовое описание. Порядок для агента описан в `CLAUDE.md`.

## Если что-то не работает

- «антибот или капча», 403, 429: площадка не пускает с вашего IP. Попробуйте позже, с `--browser` или вставьте текст вакансии в `messages/out/<вакансия>/vacancy.md` под первой строкой и запустите команду с той же ссылкой.
- «сертификат, которому система не доверяет»: сайт подписан сертификатом Минцифры. Установите его и укажите путь в переменной `NODE_EXTRA_CA_CERTS`.
- Агент не найден сразу после копирования папки: перезапустите Claude Code, агенты подхватываются при старте сессии.
- Подбор приносит не те вакансии: поправьте `messages/config/search.json` или попросите `/otklik` пересобрать его под резюме (агент `profile-builder` с заданием `search`).
